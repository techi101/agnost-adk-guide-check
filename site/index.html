Agnost's Google ADK guide works on ADK 2.15. On ADK 1.39 the answers land on the wrong span.

I ran the OpenTelemetry setup from docs.agnost.ai/google-adk exactly as written, against a local OTLP receiver, on both ADK lines. On 2.15.1 every field lands on the root span. On 1.39.1 the root span gets the user and the question, but not the answer or the conversation id. ADK still shipped 1.x releases until August 2026, so some of Agnost's ADK signups are probably on it.

The fix keeps a handle on the root span

On 1.x the final answer callback runs inside a child generate_content span, so trace.get_current_span() returns that child. Saving the root span when the user's message arrives, and writing the answer to it later, works on both lines. The plugin still only sets attributes.

How it was run, and what it does not show

Offline and repeatable

A scripted ADK model replays the same two turns every time, so no API key and no network. A small HTTP server on 127.0.0.1 stands in for otel.agnost.ai and decodes each OTLP export. The env vars and plugin are copied from the guide; only the endpoint differs.

Not checked in Agnost itself

I did not make an Agnost account, so I can't say how the dashboard shows a 1.x trace. The guide says transcripts come from the root span, which is why a missing answer there matters. A real Gemini model may also nest spans a little differently.

Why this is a growth problem

A guide that silently drops the answer means a new user's first trace looks empty. That is the activation step on the quickstart. The same harness can run every integration guide against each new framework release, every night.
