The tool calls a voice bot makes right before a call ends don't reach Agnost

Your Pipecat page says Pipecat creates no span for function execution, so Agnost "recovers each call and its result from the context of the LLM request that follows it." I tested what happens when nothing follows. On Pipecat 1.17.0, following your setup exactly, 5 of 10 tool calls in my test weren't recoverable: 4 appeared in no exported span at all, and 1 (with Claude) only in Anthropic's format, which your docs don't cover. An 80-line observer brings it to 10 of 10, in the span shape your ingest already reads.

* Your docs say recovery "works for OpenAI-compatible LLM services, which send context in OpenAI chat format." Pipecat writes each provider's own format into the llm span: OpenAI tool_calls, Anthropic tool_use blocks (tested here), AWS Bedrock toolUse and Gemini function_call parts (from Pipecat's adapter source). I counted Claude calls as not recoverable by that stated condition; if your ingest already parses Anthropic's format, those two rows change. The observer's span is the same whichever LLM the bot uses.

The three lost cases are the ones your product exists for. An end_call or transfer_call tool is how a voice bot finishes or escalates a call, and GitHub code search finds 165 public Python files containing both run_llm=False and end_call. A caller who hangs up mid-lookup and a tool cut off by an interruption are the calls where something went wrong. In all three, the LLM span that requested the tool has no output attribute, so the request itself isn't in the trace either.

The fix: one observer, no backend change

It writes each function call as an execute_tool <name> span under the current turn, with gen_ai.tool.name, gen_ai.tool.call.id, gen_ai.tool.call.arguments and gen_ai.tool.call.result. That is the shape your Vercel eve and Inngest AgentKit pages already list as "a tool call with its arguments, result, latency, and outcome". A call that is cancelled, or still open when the call ends, is closed with an error status and the reason. Each call is handled once, even though its frames pass through several processors.

"""AgnostToolSpanObserver: one OpenTelemetry span per Pipecat function call.

Why: Pipecat creates no span for function execution, so Agnost recovers a tool call from the context of the LLM
request that follows it. When nothing follows (a tool that returns with run_llm=False, such as end_call or
transfer_call; a caller who hangs up while the tool runs; a call cancelled by an interruption) the call never
reaches Agnost. This observer writes each call as an `execute_tool` span (OpenTelemetry GenAI conventions) under
the current turn, and closes any span still open when the call ends, marked as an error.

Use: PipelineWorker(pipeline, observers=[AgnostToolSpanObserver()], enable_tracing=True, ...)
"""
import json

from opentelemetry import trace
from opentelemetry.trace import Status, StatusCode

from pipecat.frames.frames import (CancelFrame, EndFrame, FunctionCallCancelFrame, FunctionCallInProgressFrame,
                                   FunctionCallResultFrame)
from pipecat.observers.base_observer import BaseObserver, FramePushed

MAX_LEN = 4000  # keep span attributes small


def _json(value):
    try:
        text = value if isinstance(value, str) else json.dumps(value, default=str)
    except Exception:
        text = str(value)
    return text[:MAX_LEN]


class AgnostToolSpanObserver(BaseObserver):
    def __init__(self, **kwargs):
        super().__init__(**kwargs)
        self._tracer = trace.get_tracer("agnost.pipecat.tools")
        self._open = {}  # tool_call_id -> span
        self._done = set()  # frames pass through several processors; handle each call once

    async def on_push_frame(self, data: FramePushed):
        frame = data.frame
        if isinstance(frame, FunctionCallInProgressFrame):
            if frame.tool_call_id in self._open or frame.tool_call_id in self._done:
                return
            tracing = getattr(data.source, "_tracing_context", None)
            parent = tracing.get_turn_context() if tracing else None
            span = self._tracer.start_span(f"execute_tool {frame.function_name}", context=parent,
                                           kind=trace.SpanKind.INTERNAL)
            span.set_attribute("gen_ai.operation.name", "execute_tool")
            span.set_attribute("gen_ai.tool.name", frame.function_name)
            span.set_attribute("gen_ai.tool.call.id", frame.tool_call_id)
            span.set_attribute("gen_ai.tool.call.arguments", _json(frame.arguments))
            if tracing and tracing.conversation_id:
                span.set_attribute("conversation.id", tracing.conversation_id)
            self._open[frame.tool_call_id] = span
        elif isinstance(frame, FunctionCallResultFrame):
            span = self._open.pop(frame.tool_call_id, None)
            if not span:
                return
            span.set_attribute("gen_ai.tool.call.result", _json(frame.result))
            error = getattr(frame, "error", None)
            if error:
                span.set_status(Status(StatusCode.ERROR, str(error)[:200]))
            if frame.run_llm is False:
                span.set_attribute("agnost.tool.run_llm", False)
            span.end()
            self._done.add(frame.tool_call_id)
        elif isinstance(frame, FunctionCallCancelFrame):
            self._close(frame.tool_call_id, "cancelled (interruption or timeout)")
        elif isinstance(frame, (EndFrame, CancelFrame)):
            for call_id in list(self._open):
                self._close(call_id, "call ended before the tool returned")

    def _close(self, call_id, reason):
        span = self._open.pop(call_id, None)
        if span:
            span.set_status(Status(StatusCode.ERROR, reason))
            span.set_attribute("agnost.tool.outcome", reason)
            span.end()
            self._done.add(call_id)

Add it with PipelineWorker(pipeline, observers=[AgnostToolSpanObserver()], enable_tracing=True, ...). Checked in the test: every tool span shares the conversation's trace and have the turn span as parent; the two parallel calls keep their own IDs, arguments and results. In the baseline cases Agnost now gets the call twice (the span and the next request's context), so the ingest should dedupe on gen_ai.tool.call.id, or the docs could say to use the observer instead of context recovery.

Why not wait for Pipecat?

Pipecat has an open pull request that adds function_call spans: #4266, opened 9 Apr 2026 by the main developer of finchvox, an open-source observability tool for Pipecat. As of 27 Nov it has no review, now conflicts with main, and has waited 232 days. Two things matter for Agnost if it ever lands: it names attributes tool.function_name, tool.arguments and tool.result, not the gen_ai.tool.* names your ingest reads for other frameworks, so it needs a mapping; and its notes say the span for an async function call ends before the final result arrives. The observer works on the Pipecat release your customers run today.

For comparison, LiveKit Agents already wraps every tool in a function_tool span with GenAI tool attributes (name, call id, arguments; voice/generation.py), so your LiveKit customers get these calls whether or not a reply follows. Pipecat is the framework where they go missing.
