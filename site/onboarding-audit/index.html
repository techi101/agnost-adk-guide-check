01
activationpatch ready

The recommended skill has no recipe for Vapi, Pipecat, Google ADK or LlamaIndex

The Pipecat, ADK and LlamaIndex docs pages each say "Recommended: Agnost AI skill", and the homepage tells every developer to install it. But references/frameworks.md has no section for any of the four, and detect.mjs doesn't recognise them. A Vapi or Pipecat team that follows the recommended path gets no platform recipe.

Evidence: frameworks.md (2,289 lines; "pipecat" appears twice, only in passing; "vapi", "adk", "llamaindex" zero times) vs docs.agnost.ai/pipecat, /vapi, /google-adk, /llamaindex.

Fix: four new recipe sections written from those docs pages, added before the last section so every existing anchor (including the ones the tests pin) stays put, with contents links and routes in SKILL.md. A second patch teaches detect.mjs to route pipecat-ai, google-adk and llama-index projects to those recipes (today a Pipecat app with an OpenAI dependency is routed to the OpenAI recipe), adds matching instrument.mjs branches, and adds three routing tests.

02
activationpatch ready

Every script command in the skill fails in Cursor

SKILL.md and the README run node "$SKILL_DIR/scripts/detect.mjs". Per issue #2, Cursor doesn't set $SKILL_DIR; an unset variable makes the path /scripts/detect.mjs and the command fails. Commands run from the customer's app root, so a bare relative path would point into their app instead.

Evidence: open issue #2. The Agent Skills spec says to reference files relative to the skill root. Fix: name the skill directory explicitly (<skill-dir>, with ${CLAUDE_SKILL_DIR} as the Claude Code form) and say why $SKILL_DIR fails.

03
trustpatch ready

Six open issues on the skill repo, 77 days without a reply

All six were filed on 11 Sep 2026 and none has a comment: missing license (#6), non-portable paths (#2), a description that under-triggers (#1), hidden scripts that contradict the contract (#3), oversized references (#4), scripts that are hard to invoke (#5). Anyone checking the repo before installing sees that.

The patch closes five: MIT license file and license field (your other public repos are MIT; your call), a description that says what and when with the platform names agents search for, the path fix, documentation of provision.mjs and run.mjs as sandbox-only, a compatibility field for Node 18 (the scripts' shared library says it needs Node 18 built-ins), and --help on all five scripts (tested in isolation: prints usage and exits before any work). #4 is left as a proposal: the tests pin anchors inside frameworks.md, so splitting it needs test changes.

04
activationpatch ready

The skill's webhook URLs for 8 voice platforms use a parameter your API spec doesn't define

For Retell, Bolna, Bland, ElevenLabs, Smallest AI, Synthflow, Cartesia and AgentPhone, the skill's recipes use ?project_id=. Your OpenAPI spec defines org_id as a required query parameter on all eight, and project_id appears nowhere in it. The Retell guide says a missing org_id returns 422. If the API matches the spec, every voice team that follows the skill's recipe gets rejected calls and an empty dashboard.

I didn't call your API, so it's possible the server still accepts project_id. Fix: patch 5 switches the eight URLs to org_id and updates the four skill-contract.mjs assertions that pinned the old name. The skill's OTLP setup also sends X-Agnost-Project-ID where every docs page uses X-Agnost-Org-ID; worth one line in the docs saying both work, if they do.

06
discoveryguide drafted

The skill has a Mastra recipe, but the docs have no Mastra page

Mastra's own docs list Langfuse, LangSmith, Arize, Braintrust, Laminar and Datadog. A developer searching "Mastra Agnost" finds nothing on docs.agnost.ai. Mastra's exporter has a custom provider (headers, protocol, endpoints.traces), so no new package is needed.

Fix: a docs page, tested locally on Mastra 1.86.0 with otel-exporter 1.6.2 and a scripted model, exporting to a stand-in receiver: 15 spans arrive with the org header; passing threadId sets gen_ai.conversation.id on every span; the chat spans carry the messages, but the root invoke_agent span carries none, so it's worth confirming the Mastra parser reads the child spans. The skill's Mastra recipe also sends X-Agnost-Project-ID where the docs use X-Agnost-Org-ID.

distributionpage drafted

Pipecat lists five eval platforms. Agnost isn't one.

docs.pipecat.ai lists Arize, Bluejay, Cekura, Coval and Roark. pipecat-ai/docs merged those pages in 0 to 7 days (#701, #705, #944, #985). Agnost has a full Pipecat guide already.

Fix: a Pipecat-format page (pipecat/evals/platforms/agnost.mdx) written from docs.agnost.ai/pipecat, every API name checked against Pipecat v1.17.0, plus the one-line docs.json change.

08
waiting in a queue

ADK docs PR #2650 is good; the queue isn't moving

It scores 98/100 on adk-docs' own integration-review checklist. The only finding: no ADK version stated, and on ADK 1.x the answer lands on a child span, not the root. 110 integration pages are waiting; no outside vendor's page has merged since 8 Sep. Full review.

The same 1.x gap is in docs.agnost.ai/google-adk itself. Fix: a drop-in plugin section that saves the root span when the user's message arrives and writes the answer there, plus gen_ai.conversation.id from the session. Tested offline on ADK 2.15.1 and 1.39.1: user, input, answer and conversation id land on the root in both (the current plugin misses the answer and conversation id on 1.39.1). The skill's ADK recipe gets the same change in patch 4.

09
sales objectioncode + tests

"Is PII redacted?" got "that's on the customer" on Launch HN

Healthcare and lending prospects ask this first. Two small recipes answer it: a wrapper around the OTLP exporter that strips emails, phone numbers (including +91 mobiles), Luhn-checked card numbers, Aadhaar and PAN from spans, and a relay for Retell and Vapi webhooks that does the same and swaps caller numbers for a salted pseudonym so calls still group by caller. 7 tests on fake data, including a local round trip through the relay.
